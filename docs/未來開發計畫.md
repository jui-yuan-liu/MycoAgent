# 未來開發計畫

對齊目前程式（0.1.0）與已落地的協作層。文件與 README 不再寫「不做 AI 切分」或「完全不做 OpenCode」：父 LLM 切分已做；OpenCode 是**可選執行器**；信箱仍不是 A2A。

## 已完成

- 群組、政策（auto／manual、allow_register、allow_parent）、核准／拒絕
- Agent 註冊、心跳、offline、同組 catalog（skills／tools／idle）
- Host 一進程多 agent；不能派給同一 `agent_id`；同機不同 agent 可互派
- HTTP 信箱、父 JobMemory、子無任務樹、父 forward（文字 + artifact id）
- 用完即棄工作區、MinIO／S3（group prefix）、假 S3 後備
- 可插拔執行器：`echo`／內建 tool loop／`opencode`
- 父 LLM 切分（無 subtasks 且有 LLM）；規劃失敗則 job failed
- `ManagerStoreProtocol`；SQLite 預設；`--db postgres://…` 可選
- `MYCOAGENT_MANAGER`／`--manager` 發現控制面
- Docker Compose：Manager + 兩 Host + MinIO
- 測試與 [入門啟用指南](入門啟用指南.md)

## 下一步（建議順序）

### 目錄依能力與負載選人

Catalog 已存 models、context_window、CPU／RAM，但派工幾乎只用 skills／tools，且 `ORDER BY name` 取第一個。應改為：可選 model／最低 context／空閒過濾，以及 round-robin 或最少 in-flight。

### 硬化（生產前）

- 子→父結果至少一次重試；派工逾時
- Agent id 持久化（重啟不要新 UUID）
- JobMemory 可選落碟
- 節點間 token 或 mTLS
- CI（pytest）
- Windows 記憶體規格偵測
- 每個 agent 一件 child → 信箱排隊或多 slot（若要同身份並發）

### 控制面叢集化（已選分階段）

Agent **現在就能**動態註冊加入。卡住的是 Manager 單寫路徑。

| 階段 | 內容 | 狀態 |
| --- | --- | --- |
| C0 | Store 介面、心跳不重寫 machine spec、DNS／env 找 Manager | 已做 |
| C1 | 無狀態 Manager 副本 + 共用 Postgres + 負載平衡 | 有 Postgres 實作，尚未做多副本部署 |
| C2 | 存活／busy 改 etcd 或 Redis lease | 未做 |
| C3 | 上千或跨區：SWIM／gossip 組員；Manager 只留建組與核准。Approve 不要走 gossip | 未做 |

不要用 LiteFS 硬撐多 Manager 寫心跳。不要把 JobMemory 搬進 Manager。不要做成完整 Akka Cluster（shard、distributed data 當任務樹）。

MinIO 自己可組 cluster，與 Manager 分開擴。

## 刻意不做（直到專門開期）

- 公用市場、計費、毒性評分
- 用 **A2A 當信箱協定**
- 把 OpenCode 當成 Cluster Manager，或讓 OpenCode 在子節點對同一 job 再派孫任務
- **巢狀父節點**（監督鏈必須回到最上層父）
- 把對話／向量記憶放進 Manager（與「不管任務內容」衝突）

## 執行器邊界

協作層保持產品核心。內建 loop 維持薄；要更強的編碼能力用 `--executor opencode`，而不是在 MycoAgent 裡複製 OpenCode 的 session／MCP／權限模型。
