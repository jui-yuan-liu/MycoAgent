# 未來開發計畫

對齊目前程式（0.1.0）與已落地的協作層。文件與 README 不再寫「不做 AI 切分」或「完全不做 OpenCode」：父 LLM 切分已做；OpenCode 是**可選執行器**；信箱仍不是 A2A。

## 已完成

- 群組、政策（auto／manual、allow_register、allow_parent）、核准／拒絕
- Agent 註冊、心跳、offline、同組 catalog（skills／tools／idle）
- Host 一進程多 agent；不能派給同一 `agent_id`；同機不同 agent 可互派
- HTTP 信箱、父 JobMemory、子無任務樹、父 forward（文字 + artifact id）
- 用完即棄工作區、MinIO／S3（group prefix）、假 S3 後備
- 可插拔執行器：`echo`／內建 tool loop／`opencode`
- 父 LLM 切分（無 subtasks 且有 LLM）；規劃失敗則 job failed
- `ManagerStoreProtocol`；SQLite 預設；`--db postgres://…` 可選
- `MYCOAGENT_MANAGER`／`--manager` 發現控制面
- Docker Compose：Manager + 兩 Host + MinIO
- 測試與 [入門啟用指南](入門啟用指南.md)
- Per-agent LLM：`--agent …,llm_url=…`（可選 `llm_model`／`llm_key`）
- Skills／tools 從檔案或目錄載入：`--skills-file`／`--tools-file`／`--capabilities-file`
- [Agent 註冊指南](agent註冊指南.md)
- 目錄選人：可選 model 名稱、最低 `context_window`、最低 `memory_mb`；派工以最少 in-flight 再 round-robin，不再固定 `ORDER BY name` 取第一個
- 硬化（部分）：子→父 `subtask_result` 至少重試一次；`--id-file`／`MYCOAGENT_AGENT_ID` 讓重啟沿用同一 catalog id；可選 SQLite JobMemory（`--job-db`／`MYCOAGENT_JOB_DB`）；GitHub Actions pytest；Windows 記憶體偵測（sysconf 沒有時走 `GlobalMemoryStatusEx`）；busy 時 in-process 信箱排隊（滿了才 409）；派工 `asyncio.wait_for` 逾時
- C1 部署：[`docker-compose.cluster.yml`](../docker-compose.cluster.yml)（Postgres + 兩份 Manager + nginx 對外一個 8080）

## 下一步（建議順序）

### 硬化（仍開放）

- 節點間 token 或 **mTLS**（尚未做；群組目前仍是信任域）
- 派工失敗後的更完整補償（assign 途中 HTTP 錯誤的狀態機）

### 控制面叢集化（已選分階段）

Agent **現在就能**動態註冊加入。C1 可用 Compose 把多個無狀態 Manager 接到同一 Postgres。

| 階段 | 內容 | 狀態 |
| --- | --- | --- |
| C0 | Store 介面、心跳不重寫 machine spec、DNS／env 找 Manager | 已做 |
| C1 | 無狀態 Manager 副本 + 共用 Postgres + 負載平衡 | 已做（見下方） |
| C2 | 存活／busy 改 etcd 或 Redis lease | **未做，仍是未來** |
| C3 | 上千或跨區：SWIM／gossip 組員；Manager 只留建組與核准。Approve 不要走 gossip | **未做，仍是未來** |

不要用 LiteFS 硬撐多 Manager 寫心跳。不要把 JobMemory 搬進 Manager。不要做成完整 Akka Cluster（shard、distributed data 當任務樹）。

MinIO 自己可組 cluster，與 Manager 分開擴。

C1 怎麼跑：不要與預設 `docker-compose.yml` 同時 `up`（都會佔 8080）。

```bash
docker compose -f docker-compose.cluster.yml up --build
```

兩份 Manager 都連 `postgresql://…@postgres:5432/mycoagent`，**不對外開埠**；`manager-lb`（nginx `least_conn`）只發布主機 `8080`。Host／`ctl` 仍打 `http://127.0.0.1:8080`（容器內用 `http://manager-lb:8080`）。映像需含 `psycopg`（Dockerfile 已裝 `[postgres]`）。

C2／C3 等規模上來再做：不要在 runtime 接 etcd 或 gossip。

## 刻意不做（直到專門開期）

- 公用市場、計費、毒性評分
- 用 **A2A 當信箱協定**
- 把 OpenCode 當成 Cluster Manager，或讓 OpenCode 在子節點對同一 job 再派孫任務
- **巢狀父節點**（監督鏈必須回到最上層父）
- 把對話／向量記憶放進 Manager（與「不管任務內容」衝突）

## 執行器邊界

協作層保持產品核心。內建 loop 維持薄；要更強的編碼能力用 `--executor opencode`，而不是在 MycoAgent 裡複製 OpenCode 的 session／MCP／權限模型。
