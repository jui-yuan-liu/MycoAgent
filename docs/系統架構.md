# 系統架構

MycoAgent 讓子任務不必只在本機執行緒平行：同群組的 agent 用 HTTP 信箱收派工。概念接近 Akka 的 mailbox 與監督在父，但**不是** Akka Cluster 移植。

## 三層

```
協作層（本專案）     執行器（可插拔）         節點間協定
群組／目錄／Host     echo / 內建 loop /      assign_subtask
JobMemory／MinIO     OpenCode                subtask_result
派工規則                                     artifact_ids
```

- **協作層必須自己做。** OpenCode 與 A2A 都不是這一層。
- **執行器可換。** 內建 loop 只是預設大腦，不是第二套 OpenCode。
- **協定是自有 JSON，不是 Google A2A。** 改 A2A 等於換線路，與換執行器無關。

## 執行時角色

```
                    ┌─────────────────────┐
                    │  Cluster Manager    │
                    │  群組政策、通訊錄    │
                    │  SQLite 或 Postgres │
                    └──────────┬──────────┘
           註冊／心跳／catalog │
         ┌─────────────────────┴─────────────────────┐
         ▼                                           ▼
┌─────────────────┐                       ┌─────────────────┐
│ Host 行程       │                       │ Host 行程       │
│ Agent A（父）   │  assign_subtask       │ Agent B（子）   │
│ JobMemory       │ ───────────────────►  │ 執行器+工作區   │
│                 │ ◄───────────────────  │ 無任務樹        │
└────────┬────────┘  result+artifact_ids  └────────┬────────┘
         │                                         │
         │              ┌──────────┐               │
         └─────────────►│ MinIO/S3 │◄──────────────┘
           下載引用     │ 產物本體 │    上傳後刪工作區
                        └──────────┘
```

| 角色 | 職責 | 狀態放哪 |
| --- | --- | --- |
| **Cluster Manager** | 建組、註冊、心跳、目錄、核准 | SQLite（預設 `mycoagent.db`）或 `--db postgres://…` |
| **Host** | 一個 OS 行程，可掛多個 agent | 行程內 |
| **Agent** | 目錄上一列：信箱、skills、models、idle／busy | 身份在 Manager；忙碌在心跳 |
| **父 agent** | 誰 `POST /jobs` 誰就是該次父；保存 JobMemory | **僅該 agent 記憶體** |
| **子 agent** | 收 `assign_subtask`，跑執行器，上傳產物，回報 | 執行期暫存目錄，結束刪除 |
| **產物庫** | blob | MinIO／S3；未設 env 則行程內假 S3 |

Manager **看不見** job 內容。兄弟 **不互連**、不交換 mailbox URL。不能派給**同一個 `agent_id`**；同機不同 agent 可以互派。

## 目錄裡的「node」

HTTP 與 SQLite 表名仍是 `nodes`，語意是 **agent**。多 agent Host 的信箱為 `{advertise}/agents/{agent_id}`；單一 `--name` 時信箱就是 advertise URL。

每列包含：名稱、群組、mailbox_url、機器規格、系統規格、models（name／local|api／可選 context_window）、skills、tools、status、membership。

Catalog 篩選：同組、已核准、可選 idle、skills、tools、排除某個 id。目前按 **name 排序取符合者**，尚未做負載感知。

## 群組政策

- `join_mode=auto`：註冊即核准。`manual`：先 `pending`，管理員核准才進目錄、才能當父。
- `allow_register` 非空：僅列出的**名稱**能註冊。
- `allow_parent` 非空：僅列出的名稱或 id 能 `POST /jobs`。
- 群組同時是**派工邊界**與**信任域**（無 token／mTLS；同組 MinIO prefix 未另做 ACL）。

## HTTP 表面（摘要）

**Manager（預設 :8080）**

- `GET /health`
- `POST/GET/PATCH/DELETE /groups`、`GET /groups/{name}`
- `POST /groups/{name}/approve/{id}`、`…/deny/{id}`
- `POST /nodes/register`、`POST /nodes/{id}/heartbeat`、`GET /nodes/{id}`
- `GET /catalog?group=&idle_only=&skills=&tools=&exclude_node_id=`

**單一 agent Host（advertise 即信箱）**

- `GET /health`、`GET /child`
- `POST/GET /jobs`、`GET /jobs/{id}`、`POST /jobs/{id}/forward`
- `POST /mailbox`

**多 agent Host**

- `GET /agents`、上述路徑掛在 `/agents/{id}/…`

## 已知限制（現況）

- JobMemory 與假 S3 在 RAM；重啟父 Host 任務樹消失。
- 回報是一次 HTTP：父當下掛了，子結果可能丟。
- 每個 agent 同時一件 child（busy 則 409）。
- 目錄選人不是 round-robin／最少負載。
- 無認證；shell／OpenCode 信任同組與本機設定。
- Manager 預設單檔 SQLite，不能多寫者水平擴（Postgres 實作已有，多副本部署見 [未來開發計畫](未來開發計畫.md)）。
