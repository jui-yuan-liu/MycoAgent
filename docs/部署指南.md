# 部署指南

一句話：**Manager**＝通訊錄；**Host**＝信箱；**MinIO**＝產物庫。`--advertise` 必須是**其他節點／Pod 連得到的 URL**（Compose 用服務名如 `http://node-a:9001`；K8s 用 Service DNS 如 `http://alpha:9001`），不能是主機上的 `127.0.0.1`。

本文件兩條路徑：本機 **Docker Compose**，以及 **Kubernetes** 純 manifests（`deploy/k8s/`）。不涵蓋 Helm、Operator、Ingress、把 oMLX 做成叢集服務。多 Manager（Postgres）見 [`docker-compose.cluster.yml`](../docker-compose.cluster.yml) 與 [未來開發計畫](未來開發計畫.md)。

---

## 路徑 A：Docker Compose

與 [快速使用指南](快速使用指南.md) 對齊；這裡只列部署步驟。

### 1. 啟動

專案根目錄：

```bash
docker compose up --build -d
```

會起 Manager、兩個 Host（alpha／beta）、MinIO。映像標籤 `mycoagent:mvp`。

### 2.（可選）對接本機 LLM

Compose **不起** AI server。Mac 上先開 oMLX，再：

```bash
docker compose exec -it node-a python -m mycoagent init --provider omlx
```

略過則 Host 以 Echo 跑（未設 `MYCOAGENT_LLM_BASE_URL` 時 `--executor auto`）。

### 3. 確認與操作

| 服務 | 主機連線 | 說明 |
| --- | --- | --- |
| Manager | `http://127.0.0.1:8080` | 群組與資源目錄 |
| alpha（node-a） | `http://127.0.0.1:9001` | 範例父 agent |
| beta（node-b） | `http://127.0.0.1:9002` | 子 agent |
| MinIO API／console | `http://127.0.0.1:9090`／`9091` | 帳密預設 `minioadmin`／`minioadmin` |

```bash
curl http://127.0.0.1:8080/health

docker compose exec node-a python -m mycoagent ctl catalog default --manager http://manager:8080

docker compose exec node-a python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

主機請打 `127.0.0.1`；容器互連才用 `manager`、`node-a` 等名字（compose 裡 `--advertise` 已是 `http://node-a:9001`／`http://node-b:9002`）。

### 4.（可選）共享 Bearer

在 `docker-compose.yml` 為 manager／node-a／node-b 設**同一個** `MYCOAGENT_TOKEN`（檔內有註解範例）。設了之後 `ctl` 也要帶同一值（環境變數或 `--token`），否則目錄／派工會 401。未設＝本機開放 MVP。

## 路徑 B：Kubernetes

範本在 [`deploy/k8s/`](../deploy/k8s/)：namespace、Secret、MinIO、Manager（SQLite PVC）、alpha／beta。預設映像 `mycoagent:mvp`、`imagePullPolicy: IfNotPresent`。對外用 `kubectl port-forward`，不強制 Ingress。

### 1. 建叢集與改 Secret

需要可跑的叢集（kind／minikube／其他）與 `kubectl`。

編輯 [`deploy/k8s/01-secret.yaml`](../deploy/k8s/01-secret.yaml)：改 MinIO 帳密；非本機請改掉範例值。`MYCOAGENT_TOKEN` 留空＝開放；要啟用時設非空字串，Manager、Hosts、ctl 必須一致。

### 2. 建映像並載入叢集

在專案根目錄：

```bash
docker build -t mycoagent:mvp .
```

依環境把映像送進節點（否則 Pod 會 `ImagePullBackOff`／找不到本機 tag）：

```bash
# kind
kind load docker-image mycoagent:mvp

# minikube
minikube image load mycoagent:mvp
```

或推到 registry，再改 Deployment 的 `image:`。

### 3. Apply

```bash
# 一次全部
kubectl apply -k deploy/k8s

# 或依序
kubectl apply -f deploy/k8s/00-namespace.yaml
kubectl apply -f deploy/k8s/01-secret.yaml
kubectl apply -f deploy/k8s/02-minio.yaml
kubectl apply -f deploy/k8s/03-manager.yaml
kubectl apply -f deploy/k8s/04-node-alpha.yaml
kubectl apply -f deploy/k8s/05-node-beta.yaml
```

等 Ready：

```bash
kubectl -n mycoagent get pods
kubectl -n mycoagent rollout status deploy/manager
kubectl -n mycoagent rollout status deploy/alpha
kubectl -n mycoagent rollout status deploy/beta
```

叢集內：`manager:8080`、`alpha:9001`、`beta:9002`、`minio:9000`。advertise 已是 `http://alpha:9001`／`http://beta:9002`。

### 4. Port-forward（從本機打）

另開終端：

```bash
kubectl -n mycoagent port-forward svc/manager 8080:8080
# 需要時再加：
# kubectl -n mycoagent port-forward svc/alpha 9001:9001
# kubectl -n mycoagent port-forward svc/minio 9090:9000
```

```bash
curl http://127.0.0.1:8080/health
```

### 5. catalog／submit

在叢集內跑 ctl（不必本機裝套件）：

```bash
kubectl -n mycoagent exec -it deploy/alpha -- \
  python -m mycoagent ctl catalog default --manager http://manager:8080

kubectl -n mycoagent exec -it deploy/alpha -- \
  python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

容器內打本機埠 `127.0.0.1:9001`（alpha 聽在自己 Pod）；其他 Pod 互連請用 Service 名。若 Secret 設了 `MYCOAGENT_TOKEN`，exec 進容器時環境變數已掛上；從本機 ctl 則需自行 export。

預設無 LLM＝Echo。oMLX **不**做成 K8s 服務；要 LLM 請在本機／外部提供並自行改 Host env（超出本範本）。

### 6. 加第三個 agent

1. 複製 `04-node-alpha.yaml` 為例如 `06-node-gamma.yaml`。
2. 改 Deployment／Service 名、標籤、`--name`、`--port`、`--advertise`（例如 `http://gamma:9003`）、Service `port`／`targetPort`、`--id-file`。
3. 把檔名加進 `kustomization.yaml` 的 `resources`，再 `kubectl apply -k deploy/k8s`。

Manager 的 `--bootstrap-group default` 已在；新 Host 用同一 `--group default` 即可入組。

### 7. 清理

```bash
kubectl delete -k deploy/k8s
```

PVC 是否一併刪除視叢集／finalizer；本機 kind 常隨 namespace 清掉。

## 常見錯誤

| 症狀 | 原因與處理 |
| --- | --- |
| 註冊成功但派工連不到同伴 | `--advertise` 用了 `127.0.0.1` 或主機名，對方解析／連不到。Compose 用服務名；K8s 用 Service DNS（`http://alpha:9001`）。 |
| Pod `ErrImageNeverPull`／找不到映像 | 忘了 `kind load`／`minikube image load`，或 registry 映像名與 Deployment 不一致。 |
| MinIO 上傳失敗／403 | Secret 裡 MinIO 帳密與 Host 的 `MYCOAGENT_S3_*` 不一致；或 `MYCOAGENT_S3_ENDPOINT` 不是 `http://minio:9000`。 |
| catalog／submit 401 | 設了 `MYCOAGENT_TOKEN` 但 ctl／某 Host／Manager 缺漏或值不同。全開或全關、同一字串。 |
| 主機 curl 連不上 K8s 服務 | 忘了 `port-forward`；或打了叢集內 DNS（本機解析不到）。 |
