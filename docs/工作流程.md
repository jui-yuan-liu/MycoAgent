# 工作流程

對照 [系統架構](系統架構.md)。下列是現行程式實際會走的路徑。

## 1. 啟動與入組

1. `python -m mycoagent manager` 建立 FastAPI，可 `--bootstrap-group default`。
2. `python -m mycoagent node …` 起 Host，為每個 agent 向 `POST /nodes/register` 登錄 mailbox、skills、tools、models、機器規格。
3. 每個 agent 背景心跳 `POST /nodes/{id}/heartbeat`（預設約 5 秒），只帶 **idle／busy** 與可選 tools／models，不重寫整份 machine spec。
4. Manager 逾時（預設 15 秒）沒心跳則標 `offline`。預設 catalog 只顯示 idle。

`join_mode=manual` 時新 agent 為 `pending`，不進目錄、不能當父，直到 `ctl approve`。

## 2. 發起任務（成為父）

對某 agent 的 `POST /jobs`：

1. 檢查 membership 為 approved，且通過 `allow_parent`。
2. 建立 **只存在此 agent** 的 `JobMemory`。
3. **子任務從哪來**
   - 請求帶了 `subtasks`：照單派。
   - 沒帶、且 Host 有 LLM planner：查同組 catalog，LLM 產出 `SubtaskSpec[]`，寫進 JobMemory 再派。規劃失敗則整份 job `failed`。
   - 沒帶、也沒 planner：本機跑執行器（通常 Echo），寫 `local_result`，不必有同伴。
4. 有子任務時：對每一筆查 catalog（同組、idle、skills／tools、排除自己的 `agent_id`），取清單第一個，`POST {mailbox}/mailbox` 送 `assign_subtask`（含 `parent_mailbox_url`、description、payload、`artifact_ids`）。
5. 沒有符合的同伴：該子任務 `failed`（例如 `no idle matching node in the same group`）。

子 agent 對同一 `job_id` 做 `GET /jobs` 或 `forward` 都是 **404**。

## 3. 子 agent 執行

```
assign_subtask
    → 標 busy（已有 child 則 409）
    → 建暫存工作區
    → 若 payload 有 artifact_ids：從 MinIO 下載進工作區
    → executor.run（echo / 內建 loop / opencode）
    → 把工作區檔案上傳 MinIO，得到 artifact_ids
    → 刪工作區
    → POST 父信箱 subtask_result（摘要 + artifact_ids，無本機路徑）
    → 標 idle
```

內建 loop：OpenAI-compatible `chat/completions` + workspace 內 `shell`／讀寫檔，預設最多 12 步。OpenCode：`opencode run --format json`，`cwd` 為工作區。

## 4. 父收結果與結束

父用 result 更新對應 `SubtaskRecord`。全部 completed → job completed；任一 failed → job failed。

## 5. Forward（同一 job 再派一筆）

只有持有該 JobMemory 的父可以 `POST /jobs/{id}/forward`。

- 可把某筆子任務的 **result 文字**與 **artifact_ids** 放進下一筆 payload（`source_subtask_id`）。
- 排除自己與來源子 agent；可指定 `target_node_id`（必須同組、已核准、idle）。
- 不把來源 mailbox URL 傳給下一個人。
- 子對同一 job forward → 404（禁止巢狀父節點）。孫任務必須再由最上層父 forward。

## 6. 產物鍵

`{group}/{job_id}/{subtask_id}/{filename}`。Manager 不存 blob。未設 `MYCOAGENT_S3_*` 時用行程內假 S3，重啟即沒。

## 與 Akka 的對照（流程視角）

| 想法 | 本專案 |
| --- | --- |
| Tell／mailbox | HTTP `Envelope`，無持久佇列 |
| 父監督 | JobMemory 在父；無 restart 策略 |
| 子不持有樹 | 子無 `/jobs` |
| 叢集成員 | 註冊 + 心跳，不是 gossip |
