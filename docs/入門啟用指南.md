# MycoAgent 入門啟用指南

這份文件帶你從零跑起本機：建群組、開兩個 Host（或一機兩個 agent）、查資源目錄、發任務、對照父／子記憶。較短的路徑見 [快速使用指南](快速使用指南.md)；新 agent 入組見 [Agent 註冊指南](agent註冊指南.md)；架構與流程見 [系統架構](系統架構.md)、[工作流程](工作流程.md)。

**現在可以做：** 父 agent 用 LLM 依目錄把 description 切成 subtasks（也可繼續用 `ctl --subtask` 顯式指定）。子執行器可選 `echo`／內建 `agent` loop／本機 `opencode`。

**仍然不做：** 公用市場、計費、毒性評分、用 **A2A 當信箱協定**、把 OpenCode 當成 Cluster Manager、**巢狀父節點**（子不可對同一 job 再派；孫任務由最上層父 forward）。

逐步指令對齊目前程式：`python -m mycoagent`、`ctl` 子命令、預設埠 `8080`／`9001`／`9002`。可用 `python -m mycoagent --help` 與 `python -m mycoagent ctl --help` 核對旗標。

---

## 這是什麼

- **群組**：一組互相看得見的 agent。Cluster Manager 管通訊錄與群組政策，不管任務內容、也不存產物檔。
- **資源目錄**：查「這個群組裡誰空閒、有哪些技能／工具」。派工只會從**同一群組、已核准、空閒、且不是同一個 agent_id**的對象裡挑。同機不同 agent 可以互派。
- **Host／信箱／父任務記憶**：一個 Host 行程可掛多個 agent，各有信箱與 idle／busy。誰發起任務，誰就是這次的**父 agent**，只有他保存該次 job 的子任務細節；子 agent 只做事、上傳產物、回報 artifact id，**沒有任務樹、也不跟兄弟互連**。
- **工作區與產物**：每個 assignment 一個暫存目錄，結束必刪。結果裡不會帶本機路徑；檔案本體在 MinIO／S3。
- **三層：** 協作（群組／目錄／信箱）是 MycoAgent；執行器可插拔；節點間 JSON **不是** A2A。內建 loop 不是第二個 OpenCode；`--executor opencode` 才會把子任務丟進本機 `opencode run`。

---

## 環境需求

擇一即可：

- **Python 3.11+**（建議用虛擬環境；本機若已有 `.venv` 可直接用）
- **Docker** 與 Docker Compose（一條指令起 Manager + 兩個 Host + MinIO）

可選：`uv`（用來裝套件）、`curl`（想打 HTTP 時）、本機 **oMLX**／Ollama／其他 OpenAI-compatible LLM（父切分與內建 agent loop；沒有時走 Echo，demo 仍可用）、本機 [OpenCode](https://opencode.ai)（僅當 `--executor opencode`）。Docker 一鍵堆疊**不包含** LLM server；Mac 上用 oMLX 時請先 `omlx start`，再看 [快速使用指南](快速使用指南.md) 的 `--provider omlx`。

## 安裝

在專案根目錄（含 `pyproject.toml` 的那層）：

```bash
python3 -m venv .venv
```

用現有 `.venv` 安裝（建議）：

```bash
uv pip install -e ".[dev]" --python .venv/bin/python
```

或啟用 venv 後用 pip：

```bash
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

之後指令可用 `.venv/bin/python -m mycoagent …`，或先 `source .venv/bin/activate` 再打 `python -m mycoagent …`。下文寫 `python` 時，請指向這個環境。

只跑 Docker、但還想在主機用 `ctl` 或 `./scripts/demo.sh`：主機也要裝一次套件（同上）。不想裝的話，改用文末「Docker 裡執行 ctl」。

檢查：

```bash
python -m mycoagent --help
```

應看到 `manager`、`node`、`init`、`ctl`。`node` 現在是 Host 行程。Docker 一鍵路徑見 [快速使用指南](快速使用指南.md)（`docker compose up --build -d` 後 `docker compose exec -it node-a python -m mycoagent init`）。

## 啟動 Cluster Manager

**一條指令（Docker）：** 開 Manager、MinIO，並自動帶上 `default` 群組與兩個 Host（下一節會用到）。

```bash
docker compose up --build -d
docker compose exec -it node-a python -m mycoagent init
```

專案與映像名稱固定為 `mycoagent`（`mycoagent:mvp`），容器為 `mycoagent-manager-1`、`mycoagent-node-a-1`、`mycoagent-node-b-1`、`mycoagent-minio-1`。沒有本機設定時 Host 以 Echo 起來；`init` 互動設定 LLM／skills 並套用到已在跑的 Host。容器內連本機 LLM 用 `host.docker.internal`。細節見 [快速使用指南](快速使用指南.md)。

主機埠：Manager `http://127.0.0.1:8080`，alpha `http://127.0.0.1:9001`，beta `http://127.0.0.1:9002`，MinIO API `http://127.0.0.1:9090`，MinIO console `http://127.0.0.1:9091`（demo 帳密 `minioadmin`）。

**三個終端（venv）— 先開 Manager：**

```bash
python -m mycoagent manager
```

等價寫法（預設就是這些值，可省略）：

```bash
python -m mycoagent manager --host 0.0.0.0 --port 8080 --db mycoagent.db --bootstrap-group default --heartbeat-timeout 15
```

`--db` 可以是 SQLite 檔路徑，或 `postgres://user:pass@host:5432/dbname`。`--bootstrap-group default` 會在啟動時建立名為 `default` 的群組（已存在則略過）。不要這個行為可另建群組，見「群組政策」。

確認：

```bash
curl http://127.0.0.1:8080/health
# {"status":"ok","role":"cluster-manager"}

python -m mycoagent ctl groups
python -m mycoagent ctl group default
```

`ctl` 預設 `--manager http://127.0.0.1:8080`。Manager 不在本機時加上 `--manager http://…`，或設 `MYCOAGENT_MANAGER`。

### 可選共享 Bearer token

未設定時 Manager／Host 維持開放（本機 Docker demo 不變）。若要在同一叢集共用一把密鑰：

```bash
export MYCOAGENT_TOKEN=changeme
# 或：python -m mycoagent manager --token changeme
#      python -m mycoagent node … --token changeme
```

設了之後：除 `GET /health` 外，Manager 的目錄／註冊／心跳等都要 `Authorization: Bearer …`；Host 的 `POST /mailbox`、`/jobs`、`/forward`、`/configure` 同樣檢查。`ManagerClient`／`MailboxClient`／`ctl` 會讀 `MYCOAGENT_TOKEN` 並帶上 header。Compose 裡有註解掉的 `MYCOAGENT_TOKEN` 範例，Manager 與各 Host 必須設**同一個**值。

## 啟動至少兩個 agent 並加入同一群組

父 agent**不能派給自己的 agent_id**，要派子任務至少需要同組另一個已核准、空閒的 agent（可以是另一台機器，或同一 Host 上的另一個 agent）。

**Docker：** `docker compose up --build -d` 已啟動 `alpha`、`beta` 兩個 Host，都加入 `default`。沒有 `agents.yaml` 時執行器為 Echo。接著可 `docker compose exec -it node-a python -m mycoagent init` 設定 LLM（見 [快速使用指南](快速使用指南.md)），或跳到「查看資源目錄」。

**venv — 終端 2（alpha）：**

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --name alpha \
  --port 9001 \
  --advertise http://127.0.0.1:9001 \
  --skills coding \
  --tools shell
```

**venv — 終端 3（beta）：**

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --name beta \
  --port 9002 \
  --advertise http://127.0.0.1:9002 \
  --skills coding \
  --tools shell
```

同一行程掛兩個 agent：

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --port 9000 \
  --advertise http://127.0.0.1:9000 \
  --agent name=alpha,skills=coding,tools=shell \
  --agent name=beta,skills=coding,tools=shell
```

此時請打 `GET /agents` 看各 agent id，任務送到 `http://127.0.0.1:9000/agents/<id>/jobs`。

說明：

| 旗標 | 意義 |
| --- | --- |
| `--manager` | Cluster Manager 的 base URL（必填；也可用 `MYCOAGENT_MANAGER`） |
| `--group` | 要加入的群組（必填；必須已存在） |
| `--name` | 單一 agent 顯示名稱（與 `--agent` 二選一） |
| `--agent` | 可重複。`name=…,skills=…,tools=…,models=…`；可選 `skills_file`／`tools_file`／`capabilities_file`、`llm_url`／`llm_model`／`llm_key` |
| `--port` | 本機聽的埠（預設 `9000`） |
| `--advertise` | **別的 agent 要呼叫的 Host 基底 URL**。單一 `--name` 時信箱就是這個 URL；多 agent 時為 `{advertise}/agents/{id}` |
| `--skills` / `--tools` | 逗號分隔，寫進資源目錄，供派工比對 |
| `--skills-file` / `--tools-file` | 本機檔案或目錄（JSON 清單、一行一名、或含 `SKILL.md` 的資料夾） |
| `--capabilities-file` | JSON `{"skills","tools"}` 或同時含兩類子目錄的資料夾 |
| `--executor` | `auto`（無 LLM 則 Echo，有則內建 loop）、`echo`、`agent`、`opencode` |
| `--opencode-bin` | `opencode` 執行檔（或 `MYCOAGENT_OPENCODE_BIN`） |
| `--opencode-timeout` | `opencode run` 逾時秒數（預設 120） |

預設 `default` 群組是 `join_mode=auto`，註冊後立刻成為已核准成員。

確認 Host 活著：

```bash
curl http://127.0.0.1:9001/health
curl http://127.0.0.1:9002/health
```

## 查看資源目錄

```bash
python -m mycoagent ctl catalog default
```

應看到 `alpha` 與 `beta`，`status` 為 `idle`，`skills` 含 `coding`，`tools_available` 含 `shell`。

常用選項：

```bash
python -m mycoagent ctl catalog default --skills coding --tools shell
python -m mycoagent ctl catalog default --no-idle-only   # 含 busy / offline
```

HTTP：

```bash
curl "http://127.0.0.1:8080/catalog?group=default"
curl "http://127.0.0.1:8080/catalog?group=default&idle_only=true&skills=coding&tools=shell"
```

目錄只列出**該群組、已核准**的成員。`idle_only` 預設為真，逾時沒心跳的 agent 會變 `offline`，不會出現在預設目錄裡。

## 在某 agent 發起任務（成為父 agent）

對 **alpha** 送 job，alpha 就是這次的父 agent；子任務會派給同組其他 agent（這裡是 beta）。

```bash
python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

`--subtask` 可重複。`|` 後面是可選技能，例如 `child work|coding` 表示描述 `child work`、技能 `coding`。沒有 `|` 就只傳描述。

回傳 JSON 裡記住 `job_id` 與 `subtasks[0].id`。子任務剛派出時狀態多半是 `running`，子 agent 做完會回報。未接 LLM 時執行器是回音：結果類似 `done:child work`，`artifact_ids` 為空。接上 LLM 後會在工作區跑 shell 等工具，結束前上傳產物。

不帶 `--subtask` 時：若已設定 `MYCOAGENT_LLM_BASE_URL`，父 agent 會查目錄並切分再派；規劃失敗則 job `failed`。未設定 LLM 時，工作留在父 agent 本機完成（Echo），不必有同伴：

```bash
python -m mycoagent ctl submit --node http://127.0.0.1:9001 --description "only me"
```

HTTP 等價（派給同伴）：

```bash
curl -X POST http://127.0.0.1:9001/jobs \
  -H "Content-Type: application/json" \
  -d '{"description":"demo","subtasks":[{"description":"child work","skills":["coding"],"tools":[]}]}'
```

服務已起來時，也可一次跑完「目錄 → 送任務 → 對照記憶」：

```bash
./scripts/demo.sh
```

腳本**不會**啟動長駐行程；Manager／Host 請用上面的三個終端或 `docker compose up`。

## 如何看父 agent 任務記憶 vs 子 agent 沒有記憶

把上一節的 `job_id` 代入：

```bash
# 父（alpha）有完整 job：描述、子任務、指派對象、結果、artifact id
python -m mycoagent ctl job <job_id> --node http://127.0.0.1:9001

# 子（beta）沒有這份記憶，預期結束碼 1，內容為 404
python -m mycoagent ctl job <job_id> --node http://127.0.0.1:9002
```

HTTP：

```bash
curl http://127.0.0.1:9001/jobs/<job_id>
# 父：JobMemory JSON

curl http://127.0.0.1:9002/jobs/<job_id>
# 子：{"detail":"job memory is not on this node (only the parent keeps it)"}
```

子 agent 當下若正在做子任務，可看：

```bash
curl http://127.0.0.1:9002/child
```

做完後 `current` 會回到 `null`，工作區目錄已被刪除。Cluster Manager **看不到** job；它只有群組與目錄。

## 群組政策（簡短）

預設 `default`：自動入組，任何人可註冊，任何已核准成員都可當父 agent 發任務。

| 欄位 | 空／預設 | 有值時 |
| --- | --- | --- |
| `join_mode` | `auto`：註冊即核准 | `manual`：註冊後為 `pending`，管理員核准才進目錄、才能當父 agent |
| `allow_register` | 空陣列 = 誰都能註冊 | 僅列出的**名稱**能註冊 |
| `allow_parent` | 空陣列 = 已核准成員都能發任務 | 僅列出的**名稱或 agent id**能當父 agent |

```bash
python -m mycoagent ctl groups-create locked \
  --description "需核准" \
  --join-mode manual \
  --allow-parent alpha

python -m mycoagent ctl groups-update default --description "一般開發"
python -m mycoagent ctl group locked
```

手動群組裡，新 agent 註冊後 `membership_status` 為 `pending`，`ctl catalog locked` 為空。從 `ctl group locked` 的 `pending_ids` 取出 id：

```bash
python -m mycoagent ctl approve locked <node_id>
python -m mycoagent ctl deny locked <node_id>
```

`allow_register` / `allow_parent` 為逗號分隔字串，例如 `--allow-register alpha,beta`。`groups-update` 傳空字串可清成「不限制」。

## 父 agent forward（簡短）

只有**保存該 job 的父 agent**可以把後續工作再派出去。兄弟互不知道對方主機或信箱；若帶 `--from-subtask`，父只把該子任務的**結果文字與 artifact id**放進下一筆 payload，不會轉交網路位址或本機路徑。

同一個 job，在父（alpha）上：

```bash
python -m mycoagent ctl forward <job_id> \
  --node http://127.0.0.1:9001 \
  --description "follow-up" \
  --skills coding
```

這會再派給同組另一個空閒 agent（兩個 agent 時通常是 beta，因為不能派給自己）。

若要把「某筆子任務的結果」帶給**另一個**同伴，加上 `--from-subtask <subtask_id>`。此時來源子會被排除，**需要第三個同組 agent**，否則會得到沒有空閒對象之類的錯誤：

```bash
# 可選：指定接收者
python -m mycoagent ctl forward <job_id> \
  --node http://127.0.0.1:9001 \
  --description "follow-up" \
  --from-subtask <subtask_id> \
  --target <第三個 agent 的 id> \
  --skills coding
```

第三個 agent 範例（終端 4）：

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --name gamma \
  --port 9003 \
  --advertise http://127.0.0.1:9003 \
  --skills coding \
  --tools shell
```

在子 agent 上對同一 `job_id` 做 `ctl job` 或 `ctl forward` 都是 404（沒有任務記憶）。這就是禁止巢狀父節點。

HTTP：`POST http://127.0.0.1:9001/jobs/<job_id>/forward`，JSON 欄位為 `description`、`skills`、`tools`、`source_subtask_id`、`target_node_id`。

## 常見問題

### advertise URL 填錯，派工失敗

`--advertise` 必須是**其他 Host（以及回報用的父 agent）連得上的基底 URL**，不是「你自己覺得的主機名稱」。

- 本機三個終端：用 `http://127.0.0.1:9001` 這種迴環位址即可（省略 `--advertise` 時也是這個規則）。
- Docker Compose：容器互連用 `http://node-a:9001`（compose 已設好）。你在**主機**查目錄、送任務請打 `http://127.0.0.1:9001`，不要打 `http://node-a:9001`（主機解析不到）。
- Host 在不同機器：advertise 要填對方可路由到的位址（區網 IP 或 DNS），不要留 `127.0.0.1`。
- 發現 Manager：用 DNS 或 `MYCOAGENT_MANAGER`，不要寫死單一 IP。

目錄裡的 `mailbox_url` 就是這個 agent 的信箱。父用它送 `POST …/mailbox`；子用父的信箱回報。

### 心跳離線，目錄是空的

Host 上每個 agent 預設約每 **5** 秒心跳（`--heartbeat-interval`）。Manager 預設 **15** 秒沒更新就標成 `offline`（`--heartbeat-timeout`）。心跳只帶存活與目前 idle／busy，不重寫整份機器規格。

離線者不會出現在預設的 `ctl catalog`（`idle_only`）。先看行程是否還在、`--manager` 是否指對，再：

```bash
python -m mycoagent ctl catalog default --no-idle-only
curl http://127.0.0.1:9001/health
```

重啟 Host 預設會拿到**新的** agent id（舊列心跳逾時後變 offline）。要沿用同一列：`--id-file`、`MYCOAGENT_ID_FILE` 或 `MYCOAGENT_AGENT_ID`。

### 不能派給自己

有 `--subtask`（或 LLM 切出的 subtasks）時，父會從目錄排除自己的 agent_id。只有一個 agent、或同伴 busy／offline／技能不符，子任務會 `failed`，錯誤類似 `no idle matching node in the same group`。再開一個同組 agent，或先做不帶 `--subtask`、也沒設 LLM 的本機 Echo 任務。

### 不能跨群組

目錄依 `--group`／`?group=` 過濾。不同群組的 agent 不會被派到。`--target` 若指向別組，會被拒絕。MinIO 物件鍵以 group 為 prefix；未另做權限時，等同組可讀彼此產物。

### 其他

- **群組不存在：** `--group` 必須先有（`manager` 的 bootstrap 或 `ctl groups-create`）。
- **pending／deny：** `manual` 群組未核准前不進目錄、不能當父 agent（發任務會 403）。
- **allow_parent：** 名單非空且自己不在其中，發任務 403。
- **任務記憶在記憶體：** 重啟父 Host 就沒了。Manager 狀態在 `--db`（預設 `mycoagent.db`）。
- **埠被占用：** 換 `--port`，並讓 `--advertise` 與對外 URL 一致。
- **回報是 at-most-once HTTP：** 父掛了，子結果可能丟（硬化放較後）。
- **`--executor opencode` 找不到指令：** 安裝 [OpenCode](https://opencode.ai) 或設 `MYCOAGENT_OPENCODE_BIN`。MycoAgent 只把 `cwd` 設成該次工作區；OpenCode 自己的權限若允許寫出該目錄，第一版不另做沙箱。父切分仍走內建 LLM planner，不會改成 A2A。

## Docker 裡執行 ctl（主機沒裝套件時）

```bash
docker compose exec node-a python -m mycoagent ctl catalog default --manager http://manager:8080

docker compose exec node-a python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

容器內 alpha 聽 `9001`，所以 `--node http://127.0.0.1:9001` 在 `node-a` 裡成立。某一台 Host 要接自己的 LLM：在該 service 設 `MYCOAGENT_LLM_BASE_URL`（以及可選 `MYCOAGENT_LLM_MODEL`／`MYCOAGENT_LLM_API_KEY`）。同一行程裡不同 agent 要不同模型，用 `--agent …,llm_url=…,llm_model=…`。詳見 [Agent 註冊指南](agent註冊指南.md)。
