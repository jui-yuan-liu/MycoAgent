# MycoAgent 入門啟用指南

這份文件帶你從零跑起本機 MVP：建群組、開兩個節點、查資源目錄、發任務、對照父／子記憶。不必先讀架構計畫。

本階段**不做**：公用市場、計費、毒性評分、OpenCode／A2A 綁定、AI 自動切分、同一任務的巢狀父節點。

逐步指令對齊目前程式：`python -m mycoagent`、`ctl` 子命令、預設埠 `8080`／`9001`／`9002`。可用 `python -m mycoagent --help` 與 `python -m mycoagent ctl --help` 核對旗標。

---

## 這是什麼

- **群組**：一組互相看得見的節點。Cluster Manager 管通訊錄與群組政策，不管任務內容。
- **資源目錄**：查「這個群組裡誰空閒、有哪些技能／工具」。派工只會從**同一群組、已核准、空閒、且不是自己**的節點裡挑。
- **節點信箱／父節點任務記憶**：每個節點都有信箱（收派工、回報結果）。誰在本機發起任務，誰就是這次的**父節點**，只有他保存該次 job 的子任務細節；子節點只做事、回報，**沒有任務樹、也不跟兄弟互連**。

---

## 環境需求

擇一即可：

- **Python 3.11+**（建議用虛擬環境；本機若已有 `.venv` 可直接用）
- **Docker** 與 Docker Compose（一條指令起 Manager + 兩個節點）

可選：`uv`（用來裝套件）、`curl`（想打 HTTP 時）。

## 安裝

在專案根目錄（含 `pyproject.toml` 的那層）：

```bash
python3 -m venv .venv
```

用現有 `.venv` 安裝（建議）：

```bash
uv pip install -e ".[dev]" --python .venv/bin/python
```

或啟用 venv 後用 pip：

```bash
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

之後指令可用 `.venv/bin/python -m mycoagent …`，或先 `source .venv/bin/activate` 再打 `python -m mycoagent …`。下文寫 `python` 時，請指向這個環境。

只跑 Docker、但還想在主機用 `ctl` 或 `./scripts/demo.sh`：主機也要裝一次套件（同上）。不想裝的話，改用文末「Docker 裡執行 ctl」。

檢查：

```bash
python -m mycoagent --help
```

應看到 `manager`、`node`、`ctl`。

## 啟動 Cluster Manager

**一條指令（Docker）：** 開 Manager，並自動帶上 `default` 群組與兩個節點（下一節會用到）。

```bash
docker compose up --build
```

專案與映像名稱固定為 `mycoagent`（`mycoagent:mvp`），容器為 `mycoagent-manager-1`、`mycoagent-node-a-1`、`mycoagent-node-b-1`，不會再用資料夾名 `AgentGraph`。

主機埠：Manager `http://127.0.0.1:8080`，節點 alpha `http://127.0.0.1:9001`，beta `http://127.0.0.1:9002`。

**三個終端（venv）— 先開 Manager：**

```bash
python -m mycoagent manager
```

等價寫法（預設就是這些值，可省略）：

```bash
python -m mycoagent manager --host 0.0.0.0 --port 8080 --db mycoagent.db --bootstrap-group default --heartbeat-timeout 15
```

`--bootstrap-group default` 會在啟動時建立名為 `default` 的群組（已存在則略過）。不要這個行為可另建群組，見「群組政策」。

確認：

```bash
curl http://127.0.0.1:8080/health
# {"status":"ok","role":"cluster-manager"}

python -m mycoagent ctl groups
python -m mycoagent ctl group default
```

`ctl` 預設 `--manager http://127.0.0.1:8080`。Manager 不在本機時加上 `--manager http://…`。

## 啟動至少兩個節點並加入同一群組

父節點**不能派給自己**，要派子任務至少需要同組另一個已核准、空閒的節點。

**Docker：** `docker compose up --build` 已啟動 `alpha`、`beta`，都加入 `default`。可跳到「查看資源目錄」。

**venv — 終端 2（alpha）：**

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --name alpha \
  --port 9001 \
  --advertise http://127.0.0.1:9001 \
  --skills coding \
  --tools shell
```

**venv — 終端 3（beta）：**

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --name beta \
  --port 9002 \
  --advertise http://127.0.0.1:9002 \
  --skills coding \
  --tools shell
```

說明：

| 旗標 | 意義 |
| --- | --- |
| `--manager` | Cluster Manager 的 base URL（必填） |
| `--group` | 要加入的群組（必填；必須已存在） |
| `--name` | 節點顯示名稱（必填） |
| `--port` | 本機聽的埠（預設 `9000`） |
| `--advertise` | **別的節點要呼叫的信箱 URL**。省略則為 `http://127.0.0.1:<port>` |
| `--skills` / `--tools` | 逗號分隔，寫進資源目錄，供派工比對 |

預設 `default` 群組是 `join_mode=auto`，註冊後立刻成為已核准成員。

確認節點活著：

```bash
curl http://127.0.0.1:9001/health
curl http://127.0.0.1:9002/health
```

## 查看資源目錄

```bash
python -m mycoagent ctl catalog default
```

應看到 `alpha` 與 `beta`，`status` 為 `idle`，`skills` 含 `coding`，`tools_available` 含 `shell`。

常用選項：

```bash
python -m mycoagent ctl catalog default --skills coding --tools shell
python -m mycoagent ctl catalog default --no-idle-only   # 含 busy / offline
```

HTTP：

```bash
curl "http://127.0.0.1:8080/catalog?group=default"
curl "http://127.0.0.1:8080/catalog?group=default&idle_only=true&skills=coding&tools=shell"
```

目錄只列出**該群組、已核准**的成員。`idle_only` 預設為真，逾時沒心跳的節點會變 `offline`，不會出現在預設目錄裡。

## 在某節點發起任務（成為父節點）

對 **alpha** 送 job，alpha 就是這次的父節點；子任務會派給同組其他節點（這裡是 beta）。

```bash
python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

`--subtask` 可重複。`|` 後面是可選技能，例如 `child work|coding` 表示描述 `child work`、技能 `coding`。沒有 `|` 就只傳描述。

回傳 JSON 裡記住 `job_id` 與 `subtasks[0].id`。子任務剛派出時狀態多半是 `running`，子節點做完會回報。MVP 執行器是回音：結果類似 `done:child work`。

不帶 `--subtask` 時，工作留在父節點本機完成，不必有同伴：

```bash
python -m mycoagent ctl submit --node http://127.0.0.1:9001 --description "only me"
```

HTTP 等價（派給同伴）：

```bash
curl -X POST http://127.0.0.1:9001/jobs \
  -H "Content-Type: application/json" \
  -d '{"description":"demo","subtasks":[{"description":"child work","skills":["coding"],"tools":[]}]}'
```

服務已起來時，也可一次跑完「目錄 → 送任務 → 對照記憶」：

```bash
./scripts/demo.sh
```

腳本**不會**啟動長駐行程；Manager／節點請用上面的三個終端或 `docker compose up`。

## 如何看父節點任務記憶 vs 子節點沒有記憶

把上一節的 `job_id` 代入：

```bash
# 父節點（alpha）有完整 job：描述、子任務、指派對象、結果
python -m mycoagent ctl job <job_id> --node http://127.0.0.1:9001

# 子節點（beta）沒有這份記憶，預期結束碼 1，內容為 404
python -m mycoagent ctl job <job_id> --node http://127.0.0.1:9002
```

HTTP：

```bash
curl http://127.0.0.1:9001/jobs/<job_id>
# 父：JobMemory JSON

curl http://127.0.0.1:9002/jobs/<job_id>
# 子：{"detail":"job memory is not on this node (only the parent keeps it)"}
```

子節點當下若正在做子任務，可看：

```bash
curl http://127.0.0.1:9002/child
```

做完後 `current` 會回到 `null`。Cluster Manager **看不到** job；它只有群組與目錄。

## 群組政策（簡短）

預設 `default`：自動入組，任何人可註冊，任何已核准成員都可當父節點發任務。

| 欄位 | 空／預設 | 有值時 |
| --- | --- | --- |
| `join_mode` | `auto`：註冊即核准 | `manual`：註冊後為 `pending`，管理員核准才進目錄、才能當父節點 |
| `allow_register` | 空陣列 = 誰都能註冊 | 僅列出的**節點名稱**能註冊 |
| `allow_parent` | 空陣列 = 已核准成員都能發任務 | 僅列出的**名稱或 node id**能當父節點 |

```bash
python -m mycoagent ctl groups-create locked \
  --description "需核准" \
  --join-mode manual \
  --allow-parent alpha

python -m mycoagent ctl groups-update default --description "一般開發"
python -m mycoagent ctl group locked
```

手動群組裡，新節點註冊後 `membership_status` 為 `pending`，`ctl catalog locked` 為空。從 `ctl group locked` 的 `pending_ids` 取出 `node_id`：

```bash
python -m mycoagent ctl approve locked <node_id>
python -m mycoagent ctl deny locked <node_id>
```

`allow_register` / `allow_parent` 為逗號分隔字串，例如 `--allow-register alpha,beta`。`groups-update` 傳空字串可清成「不限制」。

## 父節點 forward（簡短）

只有**保存該 job 的父節點**可以把後續工作再派出去。兄弟節點互不知道對方主機或信箱；若帶 `--from-subtask`，父節點只把該子任務的**結果文字**放進下一筆 payload，不會轉交網路位址。

同一個 job，在父節點（alpha）上：

```bash
python -m mycoagent ctl forward <job_id> \
  --node http://127.0.0.1:9001 \
  --description "follow-up" \
  --skills coding
```

這會再派給同組另一個空閒節點（兩個節點時通常是 beta，因為不能派給自己）。

若要把「某筆子任務的結果」帶給**另一個**同伴，加上 `--from-subtask <subtask_id>`。此時來源子節點會被排除，**需要第三個同組節點**，否則會得到沒有空閒對象之類的錯誤：

```bash
# 可選：指定接收者
python -m mycoagent ctl forward <job_id> \
  --node http://127.0.0.1:9001 \
  --description "follow-up" \
  --from-subtask <subtask_id> \
  --target <第三個節點的 node_id> \
  --skills coding
```

第三個節點範例（終端 4）：

```bash
python -m mycoagent node \
  --manager http://127.0.0.1:8080 \
  --group default \
  --name gamma \
  --port 9003 \
  --advertise http://127.0.0.1:9003 \
  --skills coding \
  --tools shell
```

在子節點上對同一 `job_id` 做 `ctl job` 或 `ctl forward` 都是 404（沒有任務記憶）。

HTTP：`POST http://127.0.0.1:9001/jobs/<job_id>/forward`，JSON 欄位為 `description`、`skills`、`tools`、`source_subtask_id`、`target_node_id`。

## 常見問題

### advertise URL 填錯，派工失敗

`--advertise` 必須是**其他節點（以及回報用的父節點）連得上的信箱 URL**，不是「你自己覺得的主機名稱」。

- 本機三個終端：用 `http://127.0.0.1:9001` 這種迴環位址即可（省略 `--advertise` 時也是這個規則）。
- Docker Compose：容器互連用 `http://node-a:9001`（compose 已設好）。你在**主機**查目錄、送任務請打 `http://127.0.0.1:9001`，不要打 `http://node-a:9001`（主機解析不到）。
- 節點在不同機器：advertise 要填對方可路由到的位址（區網 IP 或 DNS），不要留 `127.0.0.1`。

目錄裡的 `mailbox_url` 就是 advertise。父節點用它送 `POST …/mailbox`；子節點用父節點的 advertise 回報。

### 心跳離線，目錄是空的

節點預設約每 **5** 秒心跳（`--heartbeat-interval`）。Manager 預設 **15** 秒沒更新就標成 `offline`（`--heartbeat-timeout`）。

離線節點不會出現在預設的 `ctl catalog`（`idle_only`）。先看節點行程是否還在、`--manager` 是否指對，再：

```bash
python -m mycoagent ctl catalog default --no-idle-only
curl http://127.0.0.1:9001/health
```

重啟節點會拿到**新的** `id`；舊紀錄心跳逾時後變 offline。

### 不能派給自己

有 `--subtask` 時，父節點會從目錄排除自己。只有一個節點、或同伴 busy／offline／技能不符，子任務會 `failed`，錯誤類似 `no idle matching node in the same group`。再開一個同組節點，或先做不帶 `--subtask` 的本機任務。

### 不能跨群組

目錄依 `--group`／`?group=` 過濾。不同群組的節點不會被派到。`--target` 若指向別組，會被拒絕。

### 其他

- **群組不存在：** 節點 `--group` 必須先有（`manager` 的 bootstrap 或 `ctl groups-create`）。
- **pending／deny：** `manual` 群組未核准前不進目錄、不能當父節點（發任務會 403）。
- **allow_parent：** 名單非空且自己不在其中，發任務 403。
- **任務記憶在記憶體：** 重啟父節點就沒了。Manager 狀態在 `--db`（預設 `mycoagent.db`）。
- **埠被占用：** 換 `--port`，並讓 `--advertise` 與對外 URL 一致。

## Docker 裡執行 ctl（主機沒裝套件時）

```bash
docker compose exec node-a python -m mycoagent ctl catalog default --manager http://manager:8080

docker compose exec node-a python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

容器內 alpha 聽 `9001`，所以 `--node http://127.0.0.1:9001` 在 `node-a` 裡成立。
