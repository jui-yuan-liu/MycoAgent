# 快速使用指南（Docker）

主機只要有 Docker Compose，不必先裝 Python。目標路徑：`up` → `init`（可跳過）→ catalog → submit。更細的 venv 三終端、群組政策、forward、執行器選項見 [入門啟用指南](入門啟用指南.md)。架構見 [系統架構](系統架構.md)。

## 啟動

在專案根目錄（有 `docker-compose.yml` 的那層）：

```bash
docker compose up --build -d
docker compose exec -it node-a python -m mycoagent init
```

會起 Cluster Manager、兩個 Host（alpha／beta）、以及 MinIO。沒有 `.mycoagent/agents.yaml` 時 Host 先以 Echo 起來；`init` 會互動問每個 agent 的名稱、skills、tools、以及 LLM **provider**（`echo`／`omlx`／`ollama`／`custom`），寫入設定並 `POST /configure` 套用到**已在跑**的 Host，不必重開容器。已設定過則印摘要後離開（`--force` 才重跑）。

| 服務 | 主機怎麼連 | 角色 |
| --- | --- | --- |
| Manager | `http://127.0.0.1:8080` | 群組與資源目錄 |
| alpha | `http://127.0.0.1:9001` | 下面範例的父 agent |
| beta | `http://127.0.0.1:9002` | 子 agent（做事、沒有任務記憶） |
| MinIO API／console | `http://127.0.0.1:9090`／`9091` | 產物庫（帳密 `minioadmin`） |

在瀏覽器或主機上的 curl 請打 `127.0.0.1`，不要打 `http://node-a:9001`（主機解析不到）。容器互連才用 `manager`、`node-a` 這些名字。

確認：`curl http://127.0.0.1:8080/health` 應看到 `cluster-manager`。

## 本機 oMLX（Mac）

Compose **不會**起 AI server。oMLX 必須跑在 **Mac 主機**（Apple Silicon／Metal），容器經 `host.docker.internal:8000` 連過去。

```bash
omlx start   # 或開選單列 App；確認 http://127.0.0.1:8000/v1/models 有模型
docker compose up --build -d
docker compose exec -it node-a python -m mycoagent init --provider omlx
```

`--provider omlx` 會把 LLM URL 設成 `http://host.docker.internal:8000/v1`，並 `GET /v1/models` 自動選第一個聊天模型（略過 embedding／rerank）。沒寫 `--llm-model` 時用列出的第一個；有設 oMLX `--api-key` 時再加 `--llm-key`。

非互動：

```bash
docker compose exec node-a python -m mycoagent init --yes --provider omlx
```

範例設定：`.mycoagent/agents.omlx.example.yaml`。

Ollama 則用 `--provider ollama`（`11434/v1`）。自訂 URL 用 `--provider custom --llm-url …`。空 URL 或 `--provider echo` 等於 Echo。Linux 上 compose 已加 `extra_hosts: host.docker.internal:host-gateway`。設定檔在 gitignored 的 `.mycoagent/agents.yaml`。

## 範例：看目錄

另開一個終端（compose 維持在跑）：

```bash
docker compose exec node-a python -m mycoagent ctl catalog default --manager http://manager:8080
```

應看到 `alpha`、`beta`，`status` 為 `idle`，`skills` 含 `coding`。若剛跑過 `init` 並填了模型，目錄裡的 `models` 也會更新；agent id 不變。

## 範例：alpha 派一筆工給 beta

未設 LLM 時執行器是 Echo，子任務結果類似 `done:child work`。從 **node-a** 送（容器內 alpha 聽 `9001`）：

```bash
docker compose exec node-a python -m mycoagent ctl submit \
  --node http://127.0.0.1:9001 \
  --description "demo" \
  --subtask "child work|coding"
```

回傳 JSON 裡的 `job_id` 記住。`parent_node_id` 是 alpha；子任務會派給同組另一個空閒的 beta。

不帶 `--subtask` 時，沒有 LLM planner 則工作留在父本機做完，不必有同伴。

## 範例：父有記憶、子沒有

把上一節的 `job_id` 代入：

```bash
# 父（alpha）：有完整 job
docker compose exec node-a python -m mycoagent ctl job <job_id> --node http://127.0.0.1:9001

# 子（beta）：沒有這份記憶，預期結束碼 1、內容 404
docker compose exec node-b python -m mycoagent ctl job <job_id> --node http://127.0.0.1:9002
```

停服務：`docker compose down`。

## 多 Manager（C1）

預設 Compose 是**一份** Manager + SQLite。若要兩份無狀態 Manager 共用 Postgres、主機仍只開一個 `8080`：

```bash
docker compose -f docker-compose.cluster.yml up --build
```

nginx（`manager-lb`）對 `manager-1`／`manager-2` 做 `least_conn`；節點與 `ctl` 的 Manager URL 仍是 `http://127.0.0.1:8080`（容器內 `http://manager-lb:8080`）。**不要**與預設 `docker-compose.yml` 同時跑。C2／C3（lease、gossip）還沒做，說明見 [未來開發計畫](未來開發計畫.md)。
